## Likely Interview Questions

**1. Tell me about a React project you owned end-to-end.**

At Moresand Technologies, I built the React.js + TypeScript frontend for a distributed multi-tenant SaaS platform from the ground up — component architecture, Redux state management, responsive design, cross-browser compatibility, API integration, and production deployment on AWS ECS. Owned it entirely, from first component through production launch, and iterated based on client feedback across 5+ enterprise clients.

**2. How do you approach performance optimization in React?**

I start by profiling — React DevTools and Lighthouse for web vitals. Then: memoisation where computation is expensive (`useMemo`, `useCallback`, `React.memo`), lazy loading for below-the-fold components, code splitting with `React.lazy` and `Suspense`, and virtualisation for long lists. At GFG, these techniques improved site performance by 40%; at Moresand, they reduced development effort and render times by 50%. At MAQ, I applied memoisation and data fetching strategies for high-volume AI search results.

**3. Describe a time you took full ownership of a feature from scratch.**

WebHealth — a self-initiated website health auditing platform. I noticed that auditing tools (Lighthouse, security scanners, SEO checkers) required manual switching between tools, so I built a unified platform from scratch: React.js frontend, Node.js/Express.js backend, custom multi-page web crawler, Google Lighthouse integration, passive security scanning, and performance profiling, deployed on GCP. No one asked me to build it — I spotted the gap, designed it, built it, and shipped it.

**4. How do you ensure cross-browser compatibility?**

I write semantic HTML5 with progressive enhancement, use CSS resets/normalize.css as a baseline, test in Chrome, Firefox, Safari, and Edge. I avoid browser-specific CSS without fallbacks and keep feature detection via `@supports` for newer APIs. At MAQ and Techolution, I enforced cross-browser testing as a standard step in the code review checklist.

**5. Why Headout?**

The product — real-life experiences in 700+ cities — is one I actually use as a traveler. The engineering problem is legitimately interesting: high-traffic marketplace, global audience, performance-sensitive frontend where a slow load directly kills conversion. The pod model with end-to-end ownership matches the way I prefer to work. And the company is profitable and growing, which means engineering decisions are driven by product value, not survival.

**6. What is your experience with responsive design?**

Responsive design is a baseline for me, not an afterthought. At Moresand, I built responsive layouts for a multi-tenant enterprise SaaS with clients on different screen sizes. At GFG, responsive components served millions of monthly users. I use CSS Grid and Flexbox for layout, relative units (rem/%), and `clamp()` for fluid typography. I test with browser devtools and real devices.
